# 实验验证规范

本规范落实 [AGENTS.md](../../AGENTS.md) 的实验分析留痕要求，适用于本项目的隔离测试、接口联调、负载验证及其人工分析。文档排版遵循[文档撰写风格手册](../documentation.md)。

---

## 目录与原始产物

每次实验使用独立目录 `experiment/<主题>/<运行标识>/`，运行标识应能区分时间与验证场景，不覆盖既有运行。测试代码位于 `tests/`；tests、scripts 和 experiment 按当前 Git 白名单不随仓库提交，也不进入应用镜像，新克隆需另行取得工具和证据。

按实验需要保存原始请求与响应、指标、校验结果及 manifest。manifest 说明代码版本或工作区状态、非敏感配置、环境、隔离资源、输入范围、计时口径和清理状态。结果不确定、重试和失败尝试都必须保留，不能只统计最终成功次数。

不得记录实际密钥、密码或认证头。不得修改既有原始产物以迎合分析结论；正式文档引用未分发的本机产物时明确其获取边界。

---

## 隔离与清理

RabbitMQ 使用独立临时流或容器，Redis 使用随机键前缀或独立容器；附件使用临时目录，禁止把样本写入真实业务 data 路径。测试仅清理自身创建的资源，不清空共享 Redis、删除业务流或删除既有部署卷。

明确区分模拟组件、真实中间件、真实 HTTP 和真实模型的覆盖范围。正常停止恢复不能作为异常断电安全证明，模拟负载吞吐也不能作为真实模型性能。报告说明未覆盖条件与残留资源。

---

## 人工分析日志

每个运行目录只维护一个 `analysis.md`，由人工分析过程创建或追加，实验运行器不得自动生成。已有内容只追加新章节，不覆盖或改写历史。

每次分析使用带时区时间作为二级标题，例如 `## 2026-10-30T15:00:00+08:00`，至少记录：分析范围、结论摘要、关键证据、原因判断、建议措施和验证状态。实验报告相邻标题之间使用 `---` 分隔，三级小节可按需要调整，但不能省略关键证据与验证状态。

判断必须通过相对链接引用该运行目录中的原始响应、指标、manifest 或校验产物。区分可直接观察的事实和基于事实的推断，优先使用表格、计数、比例和简短片段，不复制大段模型原文。

比较多个运行时，在每个被分析目录中追加与该运行相关的结论，并通过相对链接引用其他运行目录。专题文档可以摘要已有结论，但不能替代每次运行的完整分析，也不能将未执行的检查标为通过。
