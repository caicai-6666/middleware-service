# 多轮 Agent 上下文与记忆管理规范

本规范落实 [AGENTS.md](../../AGENTS.md) 的上下文清洁要求，适用于后续新增或修改的多轮交互、函数工具、工作区及错误恢复节点。当前平台 A2A 是 Redis 消息协议，本服务不维护模型会话；下述要求不表示本项目已有 Agent 执行器。

---

## 上下文分层

| 内容 | 职责与边界 |
| --- | --- |
| 稳定规则与任务输入 | 同一任务中保持确定，只包含当前任务必要信息。 |
| 权威工作区 | 由程序维护的已校验事实和阶段结果。 |
| 正常短期记忆 | 当前阶段仍需保留的有效交互。 |
| 临时纠错记忆 | 从第一次连续失败开始的调用、反馈与修正尝试。 |
| 私有审计 | 完整保留响应、调用、反馈及错误，不作为模型记忆自动回放。 |
| 下游状态 | 只接收通过全部校验的正式结果。 |

不得使用一个无边界的消息列表同时承担工作区、纠错与审计职责。普通文本、无效调用和半成品只能进入私有审计或临时纠错范围，不能写入权威工作区或下游状态。

---

## 动作接受与错误恢复

先保留私有审计，再按节点契约验证调用协议、工具名称、参数 Schema、状态及业务规则；JSON 可解析或工具名合法不代表动作已被接受。错误反馈只说明必要的问题与修正方向，不复制完整失败输出、凭据或异常堆栈。

第一次失败时记录纠错边界，后续连续失败共用该边界。动作通过全部校验后，必须删除该边界之后的整段失败调用、反馈和修正尝试，再保存当前正确动作或依据工作区重建上下文；不能只删除最后一次错误，也不能在参数仍然错误时提前清理。

清理模型上下文时，私有审计完整保留失败轨迹与接受结果。恢复必须有明确上限，耗尽后显式失败，不补造正式结果或发布半成品。节点文档说明恢复次数、终止条件和失败出口。

---

## 检查点、并发与验证

检查点只提交已校验结果，按节点契约保留继续执行必需的精简事实；重建会话后给出明确的下一步任务。正式终态必须先通过终止条件校验。

每个并发任务分别维护正常记忆、纠错边界、恢复计数和审计，不能串入其他用户或会话的失败反馈。共享内容限于明确的只读规则或已校验工作区。

新增或修改节点时，至少验证连续不同类型错误、合法工具但参数非法、纠正成功后整段清理、权威结果保留、审计完整、并发隔离及恢复耗尽。提示词和工具 Schema 同时遵循[提示词工程规范](prompt-engineering.md)，实验记录遵循[实验验证规范](experiment.md)。
