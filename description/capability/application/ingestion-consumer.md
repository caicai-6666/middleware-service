# 入库请求消费服务

`app/service/ingestion_consumer.py` 配置入库消费，复用 `app/service/file_request_consumer.py` 实现的批量预取、逐条交付、显式确认和附件清理，由 `app/main.py` 装配为 `app.state.ingestion_consumer`。接口定义见[入库请求 API](../../api/ingestion.md)。

## 生命周期和进度

每次请求通过统一认证依赖获取平台身份，再通过 `PlatformSessionService.consumer_resources()` 校验目标流消费权限。该方法持有平台锁，在拉取或确认过程中保护长期 Consumer 不被失活清理关闭，同时串行化该平台消费操作。

Consumer 名称沿用平台资源中的 `平台代号:流名`，不会随 access_token 变化。RabbitMQ 按流和该稳定名称存储 offset；首次没有进度时从第一条现存消息开始，有进度时从已保存 offset + 1 开始。

缓存为空时建立订阅，最多收集约 2 秒，达到条数或字节上限时提前结束，随后取消订阅并保留 Consumer 客户端。credit 按数据块计数，因此回调自行检查缓存上限；超过边界的消息不缓存、不确认，下批重新读取。预取过程整体限时 15 秒。

缓存保存有序原始消息字节，仅在 pull 时解码队首。每次只交付一条，重复 pull 返回同一待确认消息；没有交付的后续缓存消息不能提前确认。格式错误的队首不跳过，返回 502。若单条消息超过字节上限，同样返回 502，不推进 offset，需调整上限或排查消息。

确认只接受已交付队首的 message_id，调用 store_offset 并回查成功后删除对应文件，清理成功才移除队首，保存最近确认结果用于重试。确认失败保留缓存。只要缓存未空，就不会重新订阅。确认操作整体限时 10 秒。

## 缓存配置

`app/config/consumer.py` 读取项目根目录 `.env`，进程环境变量优先；修改需重启。配置必须为正整数，非法配置阻止启动。

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `INGESTION_CACHE_MAX_MESSAGES` | `100` | 每个平台最多缓存的消息条数，包含当前待确认消息。 |
| `INGESTION_CACHE_MAX_BYTES` | `4194304` | 每个平台缓存原始消息字节数上限，默认 4 MiB。 |

字节上限不包含 Python 对象开销、队首 JSON 解码后的对象或 rstream 自身网络缓冲，因此不是进程总内存硬上限。Compose 已将这两个变量注入后端，可在 deploy 的 `.env` 覆盖。

## 故障与资源边界

- 拉取不推进 offset；错误消息不跳过，返回 502 供排查。
- 发布端生成唯一 message_id；注册中心按该标识幂等处理。
- 提交失败保留待确认记录，不因 HTTP 失败而假定 RabbitMQ 没有保存。
- 中间件重启后内存待确认和最近确认记录丢失，通过 RabbitMQ offset 恢复。未确认消息允许重投，不能承诺业务恰好处理一次。
- 平台失活或应用关闭时，会话服务在平台锁内调用 clear_platform，同步释放该平台的预取缓存、待确认记录和最近确认记录，再关闭客户端。重登后从 RabbitMQ 已确认 offset 的下一条重读。
- 资源与状态仍按单进程、单副本设计；同名消费进度不要被其他服务实例写入。
- Stream 保留策略可能清除尚未消费的数据，保存 offset 不会阻止过期清理。
- 本服务在 ack 回查 offset 成功后删除对应文件；附件读取由[resource 路由](../../api/resource.md)提供，审核结果单独发布。

## 验证

`tests/test_ingestion_consumer.py` 覆盖批量复用、条数和字节上限、超大消息、失活清理、逐条交付、重复拉取、错误确认、最近确认重试、提交异常、重建服务恢复进度、未确认重投、空流及异常消息。

已使用独立临时 RabbitMQ 流进行真实 HTTP 联调，验证拉取、确认、重复确认、权限拒绝、重建消费服务后的 offset 恢复与空流 204；测试结束删除临时流，不修改业务流消息。


## 确认后的文件清理

文件路径由消息中的 file_id 和 file_extension 构建，限定在 data/ingestion-request/file 目录。file_id 必须等于 message_id，且字段不得含路径分隔符；非法引用在提交 offset 前被拒绝。历史无后缀文件按 file_id 清理；没有文件引用的消息跳过此步骤。

删除在线程池执行，文件不存在视为成功。删除失败返回明确的 503 并保留队首，重复 ack 会回查已提交进度后再次删除，不重复提交。最近成功确认的重试不会重复删除文件。进度保存与文件删除不是原子事务，崩溃或会话失活可能留下文件，当前不提供后台补偿任务。
